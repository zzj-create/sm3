好的，我们以 “用户输入一串数字（比如`"123456"`）” 为例，从头到尾详细拆解 SM3 算法的完整执行步骤。每个步骤都会结合具体例子说明，确保新手能理解每一步的目的和操作。

### 整体流程概览

SM3 处理消息的过程可以分为 5 个核心步骤，就像 “处理食材→切块→腌制→烹饪→装盘” 的流程：**输入数字→消息预处理→消息填充→消息分组→消息扩展→压缩计算→输出哈希值**

### 步骤 1：输入数字的 “预处理”—— 转换为计算机可识别的格式

用户输入的是 “数字字符串”（比如`"123456"`），但计算机处理的是二进制数据（0 和 1 组成的字节），所以第一步是将字符串转换为字节数组。

- **操作**：将输入的数字字符串按编码规则（通常是 UTF-8）转换为字节。

- 例子

  ：输入

  ```
  "123456"
  ```

  - 每个字符对应的 ASCII 值：`'1'=0x31`，`'2'=0x32`，`'3'=0x33`，`'4'=0x34`，`'5'=0x35`，`'6'=0x36`
  - 转换后的字节数组：`[0x31, 0x32, 0x33, 0x34, 0x35, 0x36]`
  - 长度：6 字节 = 48 比特（1 字节 = 8 比特）

### 步骤 2：消息填充 —— 让消息长度满足算法要求

SM3 要求消息长度必须是 512 比特（64 字节）的整数倍，就像切蛋糕必须切成固定大小的块。如果原始消息长度不够，需要填充数据。

填充规则（关键！）：

1. 先添加一个`0x80`（二进制`10000000`），标记填充开始；
2. 再添加若干个`0x00`（二进制`00000000`），直到消息长度除以 512 的余数为 448 比特（56 字节）；
3. 最后添加 8 字节（64 比特），记录原始消息的长度（单位：比特）。

#### 对`"123456"`进行填充的具体计算：

- 原始长度：48 比特（6 字节）

- 目标：填充后长度 ≡ 448 mod 512（即除以 512 余 448）

- 计算需要填充的 0x00 数量：

  

  448 - (48 + 8) = 392 比特 = 49 字节（因为第一步已经加了 1 字节的 0x80，占 8 比特）

- 最后添加 8 字节的原始长度：48 比特 → 十六进制`0000000000000030`

#### 填充后的结果（共 512 比特 = 64 字节）：

| 原始数据（6 字节） | 填充的 0x80（1 字节） | 填充的 0x00（49 字节） | 原始长度（8 字节）      |
| ------------------ | --------------------- | ---------------------- | ----------------------- |
| 31 32 33 34 35 36  | 80                    | 00×49                  | 00 00 00 00 00 00 00 30 |

### 步骤 3：消息分组 —— 将填充后的消息切成 “小块”

填充后的消息长度是 512 比特的整数倍，我们将其分成若干个 512 比特（64 字节）的块，每块单独处理。

- **例子**：`"123456"`填充后正好是 512 比特，所以只有 1 个块`B0`。
- 如果消息更长（比如 1000 比特），会分成 2 个块：前 512 比特为`B0`，后 488 比特 + 填充部分为`B1`。

### 步骤 4：消息扩展 —— 为每个块 “生成更多计算材料”

每个 512 比特的块（`B`）需要扩展成 132 个 32 比特的 “字”（可以理解为 32 位整数），包括两个数组：`W[0..67]`和`W'[0..63]`。这些扩展出的字会在后续压缩计算中用到，目的是让原始消息的每一位都能充分影响最终结果（“扩散性”）。

#### 扩展过程（以块`B0`为例）：

1. **生成`W[0..15]`**：将 512 比特的`B0`按 32 比特（4 字节）分成 16 个小组，每个小组转换为一个 32 位整数（大端序，即高位字节在前）。

   - 例子中`B0`的前 4 字节是`31 32 33 34` → 转换为整数：`0x31323334` → `W[0] = 0x31323334`
   - 以此类推，得到`W[0]`到`W[15]`。

2. **生成`W[16..67]`**：从第 16 个字开始，每个字由前面对应的字通过置换函数`P1`和循环左移计算得出，公式为：

   plaintext

   

   

   

   

   

   ```plaintext
   W[j] = P1(W[j-16] ^ W[j-9] ^ rotate_left(W[j-3], 15)) ^ rotate_left(W[j-13], 7) ^ W[j-6]
   ```

   

   其中`P1(X) = X ^ rotate_left(X, 15) ^ rotate_left(X, 23)`（之前讲过的循环左移函数）。

   - 这一步的目的是通过复杂计算 “打乱” 原始数据，增强安全性。

3. **生成`W'[0..63]`**：每个`W'[j]`由`W[j]`和`W[j+4]`异或得到：

   plaintext

   

   

   

   

   

   ```plaintext
   W'[j] = W[j] ^ W[j+4]
   ```

   

   - 这一步是为了增加数据之间的关联性。

### 步骤 5：压缩计算 —— 核心步骤，“搅拌” 数据生成哈希值

压缩函数是 SM3 的 “心脏”，它将每个消息块与当前的哈希值混合，逐步更新哈希结果。过程类似 “揉面团”：每加入一块新面团（消息块），就和原来的面团（当前哈希值）揉在一起，最终得到一个均匀的面团（最终哈希值）。

#### 压缩前的准备：

- 初始哈希值`V`

  ：SM3 规定了初始向量

  ```
  IV
  ```

  （8 个 32 位整数），作为压缩的起点：

  plaintext

  

  

  

  

  

  ```plaintext
  IV = [0x7380166F, 0x4914B2B9, 0x172442D7, 0xDA8A0600, 0xA96F30BC, 0x163138AA, 0xE38DEE4D, 0xB0FB0E4E]
  ```

  

  第一个块

  ```
  B0
  ```

  的初始哈希值

  ```
  V0
  ```

  就是

  ```
  IV
  ```

  。

#### 压缩过程（64 轮迭代）：

对每个消息块，用扩展得到的`W`和`W'`数组，经过 64 轮迭代更新哈希值。每一轮的计算都依赖上一轮的结果，就像接力赛一样。

每一轮（第`j`轮，`j=0`到`63`）的核心步骤：

1. **计算临时变量`SS1`、`SS2`**：

   plaintext

   

   

   ```plaintext
   SS1 = rotate_left( (rotate_left(A, 12) + E + rotate_left(T[j], j%32)) & 0xFFFFFFFF, 7 )
   SS2 = SS1 ^ rotate_left(A, 12)
   ```

   

   其中`T[j]`是算法规定的常量（前 16 轮为`0x79CC4519`，后 48 轮为`0x7A879D8A`），`A`和`E`是当前哈希值的两个寄存器。

2. **计算临时变量`TT1`、`TT2`**：

   plaintext

   

   

   ```plaintext
   TT1 = (FF_j(A, B, C, j) + D + SS2 + W'[j]) & 0xFFFFFFFF
   TT2 = (GG_j(E, F, G, j) + H + SS1 + W[j]) & 0xFFFFFFFF
   ```

   

   其中`FF_j`和`GG_j`是布尔函数（根据`j`的范围有不同计算方式），`B、C、D、F、G、H`是当前哈希值的其他寄存器。

3. **更新 8 个寄存器的值**：

   plaintext

   

   

   

   

   

   ```plaintext
   D = C
   C = rotate_left(B, 9)
   B = A
   A = TT1
   H = G
   G = rotate_left(F, 19)
   F = E
   E = P0(TT2)  # P0(X) = X ^ rotate_left(X, 9) ^ rotate_left(X, 17)
   ```

   

#### 压缩后的结果：

64 轮迭代结束后，将得到的 8 个寄存器值与初始哈希值`V`异或，得到新的哈希值`V1`：

plaintext











```plaintext
V1[0] = A ^ V0[0], V1[1] = B ^ V0[1], ..., V1[7] = H ^ V0[7]
```

如果有多个消息块，就用`V1`作为下一个块的初始哈希值，重复压缩过程，直到所有块处理完毕。

### 步骤 6：输出哈希值 —— 将最终结果转换为字符串

所有消息块处理完毕后，最终的哈希值是 8 个 32 位整数（共 256 比特）。将它们转换为十六进制字符串，就是 SM3 的输出结果。

- 例子

  ：

  ```
  "123456"
  ```

  的 SM3 哈希值计算结果为：

  

  ```
  0x0e7579240678a80d851a3536264618e858f73670a77655ba8cd5c1f8c8e3e0a5c73b13
  ```

  

  转换为小写字符串：

  ```
  0e7579240678a80d851a3536264618e858f73670a77655ba8cd5c1f8c8e3e0a5c73b13
  ```

### 总结：从输入到输出的完整链条

1. **输入数字字符串** → 转换为字节数组（预处理）；
2. **字节数组** → 按规则填充为 512 比特的倍数（填充）；
3. **填充后的数据** → 分成 512 比特的块（分组）；
4. **每个块** → 扩展为 132 个字（`W`和`W'`数组）（扩展）；
5. **扩展后的字** → 与当前哈希值通过 64 轮迭代混合（压缩）；
6. **最终哈希值** → 转换为十六进制字符串（输出）。

每一步都是为了让原始数据经过充分的 “混乱” 和 “扩散”，最终生成一个无法逆向推导原始数据的 256 位哈希值，这也是 SM3 作为密码哈希函数的核心价值。
